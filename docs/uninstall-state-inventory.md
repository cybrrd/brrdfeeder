## Scope and notation

Aliases below resolve to repository paths at the base revision:

- `G/` = `Component/aviary/release-system/`.
- `R/` = `Component/aviary/engine/src/`.
- `I` = `Component/brrdfeeder/install/brrdfeeder-install.sh`.
- `U` = `Component/brrdfeeder/install/uninstall.sh`.
- `GPS` = `Component/brrdfeeder/install/gps-seed.py`.
- `BT` = `Component/brrdfeeder/install/bluetooth-state.py`.
- `S` = `/var/lib/brrdfeeder`; `P` = `/var/lib/brrdfeeder-updater`;
  `T` = `/var/lib/brrdfeeder-status`; `E` = `/etc/brrdfeeder`.

Owners describe the packaged deployment: root means root:root unless stated;
svc means the brrdfeeder service UID/GID. Creation modes subject to umask are
identified; existing files/directories can retain their prior modes. `record`
means non-secret operational/configuration data; `private` means restricted
state, queue or captured data; `secret` means credentials/token contents.
Directories inherit the class of their contents. Temporary contents have their
target's class and may be incomplete. A `Yes` in the final column describes the
current name/type checks only, conditional on all other uninstall validation;
it is not an endorsement of their sufficiency.

The table uses constrained writer families, not proposed shell wildcards.
Go CreateTemp suffixes are generated by the Go runtime; Python mkstemp suffixes
use its eight-character generated names. Status PID and sequence are decimal.
Configured paths cannot be exhaustively enumerated as fixed literals: status
and capture accept configured absolute paths (`R/node_config.rs:48,85,588,600`),
and Go config/CLI output paths are parameters. The table maps standard installed
roots and explicitly identifies optional/legacy placements. Test-only writers
are excluded (including `R/blue_policy.rs:253` pending-update writer).

## Safety conflicts beyond adding missing names

1. `G/storage.go:245` links `.pending-*` to `pending_update.json` before deferred
   removal of the temporary name. A crash can leave both at link count 2. `U:276`
   safe_file requires link count 1; adding `.pending-*` alone still refuses.
   This needs an explicit safe recovery/cleanup policy, not a blanket relaxation.
2. `U:523` currently accepts **every** regular non-symlink in the status tree.
   The requested unknown-file refusal regression cannot pass without narrowing
   existing behavior. `S/*.tmp` is also broad, and rejected-pending directories
   lack child-name/type enumeration. `safe_tree` validates the path and mount
   boundary, not recursive contents or per-child provenance (`U:289`).
3. Quarantining an invalid pending directory preserves potentially arbitrary
   children. A new structural inventory must distinguish generated records from
   preserved untrusted input; enumerating `entry/**` as trusted would be wrong.
